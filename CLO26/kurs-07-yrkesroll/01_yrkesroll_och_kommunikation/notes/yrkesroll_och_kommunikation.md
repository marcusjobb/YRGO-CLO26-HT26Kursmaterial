# Yrkesroll och Kommunikation

## Utvecklarens Roll — Mer än Kod

En professionell utvecklare gör mycket mer än att skriva kod. Du förväntas:

- **Felsöka och analysera** — hitta rotorsaken, inte bara symptom
- **Kommunicera tekniska beslut** — förklara varför, inte bara vad
- **Samarbeta** — code review, parprogrammering, möten
- **Estimera** — planera och prioritera arbete
- **Lära dig nytt** — tekniker förändras, du måste följa med

## Kommunikation med Intressenter

**Gyllene regeln:** Anpassa språket efter mottagaren.

| Intressent | Fokus | Undvik |
|------------|-------|--------|
| Kund/PO | Funktion, deadline, kostnad | Tekniska detaljer |
| Chef | Resurser, risker, framsteg | Kodnivå |
| Team | Implementation, arkitektur | Byråkrati |
| Användare | Att det fungerar | Hur det fungerar |

## Code Review

### Som granskare
- Fokusera på logik och design, inte kodstil
- Fråga "Varför?" istället för "Det är fel"
- Godkänn om det är bra nog — perfektion är fienden

### Som skribent
- Gör PR:er små (max 200–300 rader)
- Skriv tydlig PR-beskrivning
- Ta inte kritik personligt — det handlar om koden

## Självledarskap

Din utveckling är ditt ansvar:

- **Be om hjälp efter 20 min** — fastna inte i timmar
- **Säg till tidigt** om du inte kan leverera i tid
- **Dokumentera** vad du lärt dig varje vecka
- **Sätt mål** — vad vill du kunna om 6 månader?

## Time Management

| Teknik | Beskrivning |
|--------|-------------|
| Pomodoro | 25 min fokus → 5 min paus |
| Time-boxing | Sätt timer på uppgift |
| Eisenhower | Viktigt+Bråttom först |
| Eat the Frog | Gör jobbigaste uppgiften först |

## Viktigaste lärdomarna

- En utvecklares roll = kod + kommunikation + samarbete
- Anpassa språket — tekniska detaljer dödar möten med kunder
- Code review är lärande, inte kritik
- Du äger din egen utveckling — vänta inte på att någon annan ska pusha dig
- Bra time management gör dig mer produktiv och minskar stress
