# Publicera API:er på lokala servrar

🟢


Att skapa ett API är en sak. Att få det att fungera lokalt på din maskin, så att du kan testa det innan du släpper ut det i den vilda webben, är en annan. I den här lektionen ska vi gå igenom hur du publicerar och kör ett API lokalt, vad som händer bakom kulisserna och hur du kan se till att allt fungerar som det ska.

---

## Varför behöver vi köra API:er lokalt?

Föreställ dig att du bygger en restaurangbokningstjänst. Du har skrivit backend-koden, du har satt upp en databas, men hur testar du att API:et verkligen fungerar innan du släpper ut det till kunderna? Det är här en **lokal server** kommer in i bilden.

Ett lokalt API gör det möjligt att:

- Testa och felsöka utan att behöva en extern server
- Utveckla nya funktioner utan att störa live-användare
- Simulera riktiga HTTP-anrop
- Arbeta med front-end-utvecklare utan att behöva en publik server

Så innan vi går vidare: Nej, du behöver **inte** köpa en domän eller hyra en server för att testa ditt API. Vi kan hålla allt lokalt, rakt på din dator.

---

## Vad är en server?

En server är i grund och botten en applikation som lyssnar efter inkommande förfrågningar på en **port** och svarar på dem. När du startar en server, kan andra program (t.ex. din webbläsare eller Postman) kommunicera med den via **HTTP**.

**Tänk på en server som en servitör:**

- Du beställer mat (en HTTP-förfrågan, t.ex. `GET /menu`).
- Servitören hämtar maten från köket (ditt backend-API).
- Du får maten tillbaka på bordet (API-responsen i JSON-format).

För att vi ska kunna testa vårt API lokalt behöver vi en server som **lyssnar efter förfrågningar och svarar korrekt**.

---

## Skapa ett API med Spring Boot

Vi ska nu skapa ett enkelt API som hanterar bokningar för en fiktiv restaurang. Vi använder **Spring Boot**, som är ett populärt ramverk för att skapa API:er i Java.

---

### **Steg 1: Skapa ett nytt Spring Boot-projekt**

Vi använder **Spring Initializr** för att snabbt sätta upp ett nytt projekt.

1. Gå till [start.spring.io](https://start.spring.io/)
2. Välj följande inställningar:
   - **Project:** Maven
   - **Language:** Java
   - **Spring Boot:** 3.x
   - **Dependencies:** Spring Web, Lombok
3. Ladda ner projektet och öppna det i **IntelliJ IDEA**.

Nu har du en grundläggande Spring Boot-applikation redo att köras.

**File: projects/restaurant-api/pom.xml**

```xml
<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
    <dependency>
        <groupId>org.projectlombok</groupId>
        <artifactId>lombok</artifactId>
        <optional>true</optional>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>
```

---

### **Steg 2: Skapa en REST-controller**

Vi börjar med att skapa en enkel **controller** som hanterar bokningsförfrågningar.

**File: projects/restaurant-api/src/main/java/se/campusmolndal/restaurantapi/controllers/BookingController.java**

```java
package se.campusmolndal.restaurantapi.controllers;

import org.springframework.web.bind.annotation.*;
import java.util.List;
import java.util.ArrayList;

/**
 * REST Controller for handling restaurant bookings
 * Author: Marcus Medina, Campus Mölndal
 * Created: 2025-03-10
 */

@RestController
@RequestMapping("/bookings")
public class BookingController {

    private final List<String> bookings = new ArrayList<>();

    // GET: Fetch all bookings
    @GetMapping
    public List<String> getBookings() {
        return bookings;
    }

    // POST: Create a new booking
    @PostMapping
    public String createBooking(@RequestParam String name) {
        bookings.add(name);
        return "Booking created for " + name;
    }
}
```

#### Vad gör koden?

- `@RestController`: Markerar klassen som en API-controller.
- `@RequestMapping("/bookings")`: Sätter bas-URL:en för API:et.
- `@GetMapping`: Hanterar GET-förfrågningar och returnerar alla bokningar.
- `@PostMapping`: Hanterar POST-förfrågningar och sparar en ny bokning.

---

### **Steg 3: Konfigurera servern**

Spring Boot använder som standard **port 8080**, men vi kan ändra det i `application.properties`.

**File: projects/restaurant-api/src/main/resources/application.properties**

```
server.port=8081
```

Om du ändrar porten till 8081, kan du nu köra servern på `http://localhost:8081`.

---

### **Steg 4: Starta servern**

Öppna terminalen i IntelliJ IDEA och kör:

```bash
mvn spring-boot:run
```

Om allt fungerar, ska du se något liknande:

```
Tomcat started on port 8081
Application started successfully!
```

Ditt API är nu igång!

---

### **Steg 5: Testa API:et med Postman**

Nu ska vi skicka en förfrågan för att testa vårt API.

1. **Hämta alla bokningar**

   - Metod: `GET`
   - URL: `http://localhost:8081/bookings`

   **Svar:**

   ```json
   []
   ```

2. **Skapa en bokning**

   - Metod: `POST`
   - URL: `http://localhost:8081/bookings?name=Marcus`

   **Svar:**

   ```
   Booking created for Marcus
   ```

3. **Hämta alla bokningar igen**

   - Metod: `GET`
   - URL: `http://localhost:8081/bookings`

   **Svar:**

   ```json
   ["Marcus"]
   ```

Nu har vi skapat och hämtat bokningar via vårt API!

---

## Vad händer bakom kulisserna?

När vi startar vår server:

1. **Spring Boot startar en inbyggd Tomcat-server** som lyssnar på port 8081.
2. **Servern väntar på HTTP-förfrågningar**.
3. **När vi skickar en GET- eller POST-förfrågan**, hittar Spring Boot rätt metod och skickar tillbaka ett svar.

---

## Hur kan vi förbättra detta?

Just nu saknar vårt API vissa funktioner:

- **Felhantering** (Vad händer om en bokning saknas?)
- **Databasstöd** (Vi sparar bara bokningar i minnet)
- **Autentisering** (Alla kan skapa bokningar)

I nästa lektion ska vi **lägga till en databas** så att våra bokningar sparas även efter att servern stängs av.

---

## TLDR

- Vi skapar en lokal server med **Spring Boot** för att köra vårt API.
- API:et hanterar **bokningar** och kan svara på GET- och POST-förfrågningar.
- **Spring Boot har en inbyggd server (Tomcat)** som lyssnar på en specifik port.
- **Postman används för att testa API:et** genom att skicka HTTP-förfrågningar.
- API:et kan förbättras med **felhantering, databasstöd och autentisering**.

Nu är du redo att publicera och testa API:er lokalt! 🚀
