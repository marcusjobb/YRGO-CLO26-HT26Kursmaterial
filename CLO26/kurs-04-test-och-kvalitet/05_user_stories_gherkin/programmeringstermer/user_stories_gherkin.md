# 05 User Stories Gherkin — Programmeringstermer

## User Story
Krav beskrivet ur användarens perspektiv: 'Som [roll] vill jag [funktion] för att [nytta]'.

## INVEST
Kriterier för bra user stories: Independent, Negotiable, Valuable, Estimable, Small, Testable.

## Acceptance Criteria
Villkor som måste uppfyllas för att en user story ska anses komplett.

## Gherkin
Affärsläsbart språk (Given-When-Then) för att beskriva testscenarier.

## Given
Gherkin-nyckelord som beskriver förutsättningarna (Arrange). Exempel: 'Given användaren är inloggad'.

## When
Gherkin-nyckelord som beskriver händelsen (Act). Exempel: 'When användaren klickar på Spara'.

## Then
Gherkin-nyckelord som beskriver förväntat resultat (Assert). Exempel: 'Then meddelandet visas'.

## Scenario
Ett specifikt exempel på beteende i Gherkin. Varje testfall blir ett scenario.

## Scenario Outline
Gherkin-mall för att köra samma scenario med flera datakombinationer.

## BDD
Behavior-Driven Development. Utvecklingsmetod där beteende definieras i affärsspråk före implementation.
