# 02 Designmonster — Programmeringstermer

## Design Pattern
Återanvändbar lösning på ett vanligt förekommande problem inom mjukvarudesign.

## Singleton
Creational pattern som säkerställer att en klass bara har en instans och ger en global åtkomstpunkt.

## Factory Method
Creational pattern som definierar ett gränssnitt för att skapa objekt, men låter subklasser bestämma vilken klass som instantieras.

## Repository Pattern
Abstraktionslager mellan databas och applikation. Döljer databasdetaljer bakom ett rent gränssnitt.

## Strategy Pattern
Behavioral pattern som låter dig byta algoritm vid runtime genom att encapsulera dem i egna klasser.

## Observer Pattern
Behavioral pattern där ett objekt (subject) meddelar en lista av observatörer om tillståndsändringar.

## Dependency Injection
Teknik där objekt får sina beroenden utifrån istället för att skapa dem själva. Möjliggör lös koppling.

## MVC Pattern
Model-View-Controller. Separerar applikation i tre delar: data (Model), presentation (View) och logik (Controller).

## SOLID
Fem designprinciper: Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation, Dependency Inversion.

## Anti-pattern
Vanlig men ineffektiv lösning på ett återkommande problem. Exempel: God Object, Spaghetti Code.
