## Faciliteringsguide

Det här är sammanfattningen av hela diskutera-serien. Alla trådar möts här:
- Kommunikation (kunden ringde Viktor direkt — fel kanal)
- AI-kodning (förstå vad du pushar)
- GDPR (kunddata exponerades)
- Git (loggarna visar alltid vem som pushade)
- Ansvar (Viktor, företaget, processen)
- Integritet (berätta eller hoppas att ingen märker)

**Bra avslutning:** Systemen skyddar oss från varandra och från oss själva. Pull requests, code review, branch protection — de är inte byråkrati. De är Viktor-skydd.

**Kör övningen i tre delar** — pausa efter varje akt och låt gruppen diskutera innan du fortsätter. Akterna bygger på varandra.

**Akt 1 — fel Kalle gör:**
1. Tar ett direktsamtal utan ärendehantering
2. Testar inte ordentligt (buggen "syns inte" ≠ buggen är fixad)
3. Pushar direkt till main utan review
4. Förstår inte vad AI:n faktiskt gjorde

**Akt 2 — konsekvenser:**
Det räcker inte att ändra koden — datan i databasen är redan skadad. Det är skillnaden mellan att stänga en öppen dörr och att fixa ett hus där alla redan gått in.

**Akt 3 — loggarna ljuger aldrig:**
Git-loggar är tidsstämplade och signerade. Man kan inte "ta tillbaka" en commit som om den aldrig hände. Ärlighet är inte bara etisk — det är det enda rationella valet när loggarna redan har svaret.

**Kopplar till:** branch protection, pull requests, code review, GDPR, autentisering, edge case-testning (testa som *alla* roller, inte bara din).
